## ❌ Not fixed — and why

### A. Needs a reference / spec from QC (can't fix blindly)

- **"Two-line silkscreen."** Our silk deliberately draws 2 clipped lines (top + bottom
  body edges; left/right are covered by pads) — a legitimate leadless style. Whether
  it should be a different style (corner brackets, etc.) depends on what the **reference
  part's silkscreen** looks like. Need the reference silk image to match it; changing it
  blindly risks breaking the FP-07 silk-over-pad clearance rule.

- **"Symbol too big."** The symbol body (30 mm) is larger than the pin span (~20 mm).
  Shrinking it is possible, **but** it conflicts with the (now larger, KLC-correct) pin
  text drawn *inside* the body — a smaller body makes inside names collide in the middle.
  Getting this right is a layout trade-off that needs a **sizing spec** or visual
  iteration on the rendered symbol, not a blind constant change. (Related: pins are
  slightly off-center / "bottom-left pin at corner" — same body-sizing problem.)

### B. Needs a QC / product decision (not a defect)

- **"Pin sequence not correct" (symbol).** The pin *numbering* is correct (verified
  against the datasheet). The symbol arranges pins by **function** (power top, ground
  bottom, inputs left, outputs right) — our deliberate, conformance-enforced convention —
  rather than the datasheet's physical pin order. Both are valid conventions. QC must
  decide which the product should use; switching would change every part's symbols.

- **Corner pads slightly shorter than the rest (0.725 vs 0.8 mm).** This is the IPC FP-14
  corner-clearance relief (keeps ≥0.15 mm copper gap at the quad corners). Making them
  uniform means relaxing that clearance rule — a decision/risk, not a clear fix. Kept
  IPC-safe for now.

### C. Not our output — platform / frontend (rendering)

We emit geometry and layer assignments; the editor applies colors and materials. These
are rendering, not our data, so they can't be fixed in the parser:

- 3D body shown **silver instead of black**
- Pins shown **white instead of silver**
- Pads shown **red**
- Top/bottom layer and paste-mask **colors differing** from the reference
- General "physical appearance / color not the same"

# 693072010801 (Würth microSD connector) QC — Fix Status

**This part is blocked — not a code tweak.** The QC image shows our part built as a
through-hole DIP-8 (round drilled pads, 2 columns, no shield pads); the actual part is
an SMD microSD connector (8 signal pads in a row + 4 shield/mount pads S1–S4).

## Root cause

Our parser supports **ICs only** — there is **no connector/microSD package type**
(`microSD`/`connector` → "Unknown package type"). So the connector datasheet is
classified as a generic **DIP-8**, which is **through-hole**. Every QC point flows from
that: wrong mount (TH not SMD), wrong symbol (IC 2-column, not all-pins-one-side), wrong
shape/size, and no shield pads.

## ❌ Not fixed — and why (nothing cleanly fixable here)

| QC item | Why not fixed |
|---|---|
| Pins should all be on left (symbol) | Connector symbol convention; parser draws IC-style symbols. **Needs connector support.** |
| Symbol shape / size / thin lines | Drawing an IC body, not a connector. Same as above. |
| Through-hole instead of SMD (2D) | Resolves to **DIP-8** (through-hole) — no connector/SMD-connector package type to resolve to. |
| Missing shield pads S1–S4 | Needs the **Würth recommended land pattern** (vendor mechanical drawing). |
| 2D / 3D not same | Ours is a through-hole IC; actual is an SMD connector — fundamentally different. |

## What it would take (two separate things we don't have)

1. **Connector-aware handling** — a new capability (all-pins-one-side symbol, SMD
   connector land pattern, shield/mount pads). This is a feature, not a tweak.
2. **The Würth SOT/mechanical drawing** — exact SMD land, shield-pad positions, body
   size.

## Summary
- **0 issues fixed** — this part is categorically unsupported (connector) **and**
  vendor-data-limited. Forcing SMD alone would still produce a wrong generic IC, not a
  microSD connector. Recommend scoping **connector support** as a separate feature and
  sourcing the Würth land pattern before revisiting.
